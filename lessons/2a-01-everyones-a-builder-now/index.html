Module 2 · Everyone’s a builder · Lesson 2A.1

Everyone’s a builder now

You can build a working tool by describing it. The skill is knowing what to ask for and how to check it.

How it works

1

Then: hire someone, wait months.

Not long ago, a small custom tool meant learning to code or paying someone who could. Even a simple app took weeks of back and forth.

How it works

2

Now: describe it, test it, fix it.

AI coding tools write the code from a plain description. You try what they built, say what’s wrong, and they fix it. A small, useful tool can take an afternoon.

How it works

3

The hard part moved.

Typing the code is now the easy part. Deciding exactly what you want, and noticing when it isn’t right, is the work.

Good to know

What “building” means here

Small tools for yourself or your team, like a form, a tracker, a calculator or a little website. Not the next big app. Start there.

What experience teaches

The hard part moved.

I’m a researcher, not a trained programmer, and I’ve built offline games for seniors, a to-do app and this website this way. The code was rarely the problem. The problems came when I hadn’t said clearly what I wanted, and when I didn’t check what it built.

So the skills that matter now are old ones: describing a problem clearly, and testing like a careful customer.

Try this · 1 of 2

Build something tiny

Make me a simple web page that counts down the days to [a date that matters to you]. Put everything in one file I can open in my browser.

Save the answer as a file ending in .html and open it.

You’ll see a working page, built from one sentence.

Try this · 2 of 2

Let it ask first

Before writing any code, ask me five questions about what I want this page to do.

You’ll see questions you hadn’t thought of. That’s the real work.

Why: building now starts with describing, and describing well starts with questions.

The catch

Building something is easy now. Keeping it working, safe and private isn’t. A tool that handles other people’s data, money or health needs much more care, and sometimes a professional.

Start with tools only you use.

Remember

The hard part moved. It used to be writing the code. Now it’s deciding what you want and noticing when it’s wrong.
